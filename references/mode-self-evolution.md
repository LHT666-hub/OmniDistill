# Self-evolution mode

Treat feedback as observations, not immediate truth.

## Lifecycle

| State | Entry condition | Exit condition |
|---|---|---|
| observation | one correction, failure, or preference | repeated in another task |
| candidate | at least two independent tasks support it | explicit test and no unresolved contradiction |
| tested | a repeatable check exists | accepted by reviewer or policy owner |
| accepted | approved, scoped, and versioned | new evidence triggers revision |
| revised | replacement keeps lineage | superseded version retained |
| deprecated | no longer applicable | archive only |

## Safeguards

- separate user preference from objective project rule;
- record environment and date for tool failures;
- deduplicate semantically equivalent rules;
- route contradictions to human review;
- expire environment-specific rules after relevant upgrades;
- redact secrets and personal identifiers from logs.
